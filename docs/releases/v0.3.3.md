# FINOS MCP v0.3.3

Release candidate: not yet published. Python 3.12 or later is required.

This maintenance release refreshes bundled FINOS standards and preserves
readable AI governance labels after an upstream configuration change. The three
MCP servers remain read-only and work offline after installation, without a paid
model or API key.

## Changes

- AIGF v3 upstream snapshot: 24 risks, 25 controls and 13 reference frameworks.
  Preserve human-readable risk/control type labels with both v2 and v3 config
  keys; new v3 keys take precedence. Upstream domain/lens metadata is retained
  in the sources; no new domain/lens filters are added.
- CDM 7.9.0 primary schemas and samples, with CDM 6.32.0 legacy validation.
  Counts remain 767 types, 1,143 primary schemas and 1,066 legacy schemas.
  Parsed schema payloads and sample validation outcomes are unchanged from
  7.8.0 / 6.30.0; known upstream workarounds remain necessary.
- Weekly upstream sync preserves a complete recovery patch before creating its
  review PR and explains recovery when GitHub blocks PR creation.
- Claude Code and Codex plugin packaging is available in the repository. Plugin
  install recipes remain pinned to verified v0.3.2 until separately updated.
- Dependency updates and clearer directory guidance: Glama's Remote label means
  remote-capable, and does not claim a project-operated public endpoint.

## Release preparation

All six workspace versions, the dependency lock and the three candidate Registry
manifests target 0.3.3. The four distributable packages are core, AIGF, CDM and
FDC3; core is a library, not a fourth MCP server. Public install recipes and
read-only public audits intentionally stay at v0.3.2 until publication is verified.

After an approved release has published successfully, install the servers needed:

```bash
uvx --python 3.12 'finos-mcp-aigf==0.3.3'
uvx --python 3.12 'finos-mcp-cdm==0.3.3'
uvx --python 3.12 'finos-mcp-fdc3==0.3.3'
```

Preparing or merging this release does not publish to PyPI, GHCR, GitHub Releases
or the MCP Registry. Registry publication requires separate approval after the
public PyPI descriptions and ownership markers are verified.
