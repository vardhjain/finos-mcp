# FINOS MCP v0.3.2 — proposed release notes

**Draft only.** This file prepares a possible v0.3.2 release. It is not a
publication notice; no PyPI package, container image, GitHub Release, MCP Registry
entry or tag is created by this pull request. Release requires separate approval.

## Why this release exists

v0.3.1 was published before the three server package READMEs acquired their
exact `mcp-name` ownership comments. The official MCP Registry checks the
description of the **public PyPI version**, not just the source repository.
Already-uploaded PyPI files cannot be modified. A new version is therefore
necessary before the project can register its three independent servers.

## Changes prepared

- Synchronize all six workspace projects to v0.3.2 and increase the minimum
  `finos-mcp-core` dependency for AIGF, CDM and FDC3.
- Prepare v0.3.2 draft Registry metadata for each independent stdio server.
- Carry the existing source README ownership markers into new build artifacts.
  The release-preflight workflow inspects both wheels and sdists before any
  publication; the public PyPI audit must be rerun **after** any approved upload.
- Keep the production MCP tools, vendored standards and read-only security
  protections unchanged from v0.3.1.

## Post-approval installation

Only **after** v0.3.2 is published and verified on PyPI:

```bash
uvx --python 3.12 'finos-mcp-aigf==0.3.2'
uvx --python 3.12 'finos-mcp-cdm==0.3.2'
uvx --python 3.12 'finos-mcp-fdc3==0.3.2'
```

All three packages require `finos-mcp-core>=0.3.2` and Python 3.12+.

## Required checks before any release

1. Merge and verify the public PyPI ownership audit (PR #44) and
   built-artifact marker gate (PR #45) **before** merging this candidate.
2. Require green cross-platform CI, `release-preflight`, official Registry
   validation, `uv lock --check` and `python scripts/release_check.py --tag v0.3.2`.
3. Inspect the proposed wheel/sdist artifacts and confirm all four v0.3.2
   versions are not already published.
4. Obtain the owner's explicit approval to run the guarded release workflow.
   Do not push a tag merely to test.
5. If approved and published, check the live public PyPI descriptions for all
   three `mcp-name` markers. Registry registration needs **separate** approval.

The servers are independent community software, **not affiliated with or
endorsed by FINOS**.
